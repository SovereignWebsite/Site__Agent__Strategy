# Starting a fresh d.strategy session

For a fresh session started with this repository (SovereignWebsite/Site__Agent__Strategy) and one line pointing here. Everything d.strategy knows is committed: here, and (until it moves) in PrompTugal/PrompTugal__News__Website under board/team/strategy.d/. A session's memory is not state.

1. Read CLAUDE.md, then this folder: agent.json, role.md, decisions.md, learnings.md, messages.md. Then https://decisions.agents.sovereignweb.site/how-it-works/ in full (network needed; the signers check also fetches the IaC's team/keys.json).
2. Read the work so far: clone https://github.com/PrompTugal/PrompTugal__News__Website (dev) and read board/team/strategy.d/ (status.json first, then the latest debrief in debriefs/, then maps/ and strategy/). The maps are README.md for readers and map.json as data.
3. Make your own key where you run: `pip install sgit-ai==0.27.0`; `sgit pki keygen --label strategy.d@AgentiCCells.dinis` (it needs SG_SEND_PASSPHRASE: a random passphrase in a mode-600 file outside any repository, never printed). Write the git signing half in OpenSSH form, unencrypted, to a mode-600 file outside any repository (for example ~/.sw-secret/signing; the cryptography package can convert sgit's signing_private.pem). Check `ssh-keygen -y -f <file>` against the bundle's sign key. If ssh-keygen is missing: `apt-get install openssh-client`.
4. Publish the public half. The signers check lets a key vouch for itself only in a commit that ADDS a new file; replacing site/keys/strategy.d.json is a modification and is checked against the key already there. So: (a) best, while the old session is alive, it commits the new public bundle into site/keys/strategy.d.json, signed by the OLD key, as its hand-over; (b) otherwise the commit needs an `Owner override: <Dinis's words>, <where recorded>` line, so file a decision request here first and send its link through d.decisions. The file holds agent, status "active", your session URL, bundle (with sign) and ssh_signing (ecdsa-sha2-nistp256, from bundle.sign). Name the old fingerprint and the retirement time in the message. Update agent.json. In PrompTugal__News__Website, mark the old board/keys.json entry superseded and add the new one; that repository signs with a separate ed25519 key made by newsroom/tools/signing-setup.sh, which needs an active entry first. Your session URL: the get_session tool (claude-code-remote) with no session_id.
5. In this clone only: `git config gpg.format ssh`, `user.signingkey <file>`, `commit.gpgsign true`, `gpg.ssh.program ssh-keygen`. Trailers on every commit: `Agent: strategy.d@AgentiCCells.dinis` and `Claude-Session: <your session URL>`.
6. Before each push here: `node .github/ci/build.mjs && node .github/ci/share-check.mjs _site && node .github/ci/quality.mjs _site && npx --yes html-validate@8.24.0 --config .github/ci/htmlvalidate.json "_site/**/*.html"`, then `node .github/ci/signers.mjs $(git rev-parse origin/dev) HEAD`. Delete _site/ before committing. Push to dev only. Pages for account D live under site/accounts/d/ (hand-written HTML on the same shell as /accounts/b/).
7. Open work: agent.json (waiting_on) and two requests, site/decisions/requests/2026-11-24__openrouter-written-question.json and site/decisions/requests/2026-11-24__frameworks-word-and-wardley-site-name.json (the twin-* files there are b.strategy's). Next step: move the maps and strategies from PrompTugal board/team/strategy.d/ into pages under site/accounts/d/, one per commit, each copying the shell of site/accounts/d/index.html, linked from it. The PrompTugal originals stay (nothing is deleted); add a line in their README pointing to the new page. d.strategy reviews its own pages; agents.json needs no change for new pages.
8. Tell d.helm (https://claude.ai/code/session_015gaHdbUFC93JvpTQHrx8WV) and cl-4.maestro (https://claude.ai/code/session_015gaHdaUZWyhvN7nQ4fEmMo; it alone runs on a schedule and wakes the others by message) one line each: the link to this area and that you have taken over. Log every message in messages.md. Asks for Dinis's yes go as a request file here, the link through d.decisions (https://claude.ai/code/session_015gaHdaiX9VvjVwHaNezGJG).

Times always from `date -u`, read in the same command that writes them. Never: send anything outside the team, name a private person or prospect, state a fact or figure without its source and date read, use a connector, read a transcript, or start a session, scheduled task or workflow.
